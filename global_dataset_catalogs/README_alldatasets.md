# AMADEUS Global + Dataset Catalog: current implementation

This README describes the current catalog contents verified from the local YAML files and active policies on **2026-11-10**. “Included” means a record is present in the catalog; it does not mean every value, decoder, access route or database operation is verified.

## Authoritative sources

- [global_catalog.yaml](global_catalog.yaml) is the assembled full catalog and count source; its records equal the deduplicated family union and the [matching global YAML](../validated_catalog_handles/global_catalog.yaml).
- The [dataset specification YAML files](.) are authoritative for family membership, registered products, canonical definitions, native bindings and Assets. Their deduplicated union matches the global YAML exactly.
- The [discovery-handle YAML files](../validated_catalog_handles/) contain the same source/product/grid records as their matching full specifications. All 23 projections match.
- [policy.json](../catalog_gap_resolution/policy.json) supplies the current `mod13a2`, `gridmet_drought` and `pdsi_fix` settings. The [integration marker](../dataset_spec_objects/integration_20261107/active.json) and [inventory marker](../dataset_spec_objects/inventory_extension_20261107/active.json) identify the enabled extension families; every listed family has a current specification and handle.
- The current full specifications are in this directory. The [implementation record](catalog_implementation_20261110/README.md) documents earlier bounded metadata work; the [current CropScape record](cropscape_review_20261110/README.md) documents its subsequent access/legend update. Earlier overlays and field ledgers are historical evidence; their replay scripts target the former specification location and must not overwrite the current profiles.
- [amadeus_schema.yaml](../amadeus_schema/src/amadeus_schema/schema/amadeus_schema.yaml), [amadeus_catalog.yaml](../amadeus_schema/src/amadeus_schema/schema/amadeus_catalog.yaml) and [amadeus_common.yaml](../amadeus_schema/src/amadeus_schema/schema/amadeus_common.yaml) define the container, catalog classes and shared vocabulary. The [validator’s DATASETS registry](../validated_catalog_handles/validate_catalogs.py) matches the 23 specification filenames.

Current YAML records determine actual membership and counts; active policies determine enabled selections. They take precedence over narrative documentation. No membership or policy conflict was found in this inspection. Workbooks, audit summaries and documentation are not used to override these current definitions.

## Current implementation and verification

All seven [AQS products/bindings](aqs.yaml) now explicitly describe discovery metadata, the analysis-specific parameter/duration/standard/event/POC/method/unit contract, local-standard dates, source datum and file/row revision context. The catalog describes how to identify the original bulk filename from the existing access base, parameter and requested reporting year. P6M is nominal bulk publication cadence; P1D is daily summary support. No universal native CRS, final status or new metadata-gap flag was added. `process_aqs()` already transforms NAD83 to WGS84 and retains WGS84 input; the outstanding issue is executable row selection/context preservation, not a missing known-datum transformation.

The [CropScape profile](cropscape.yaml) now points to the current USDA national-download index and remains limited to native 30 m CONUS map years 2008–2023. Original 2019/2023 archive metadata and world files were inspected with bounded byte ranges. Their world files agree, but complete TIFF directories/pixels and geometry invariance across all sixteen years were not verified. Shared array dimensions/origins and a common series revision remain unset. The legend explicitly distinguishes background, clouds/no-data and valid non-crop classes; it is not observation QA. [Evidence, validation and rollback](cropscape_review_20261110/README.md).

Six MODIS QA bindings now carry partial version-specific bit-layout/source/companion information; their remaining-extraction flags and the FineModeFraction investigation flag are retained. MOD11 C6 versus v61 bits 2–3 remain discrepant. NOAA's [EDDI correction advisory](https://psl.noaa.gov/eddi/warn.html) is recorded for its NLDAS-driven archive and is not transferred to GridMET. Native datum/definition/category/normalization questions remain qualified where evidence is insufficient.

The current catalogs pass metadata schema/reference, exact global/handle projection, YAML/JSON and all 23 RDS checks. Descriptions and formulas remain declarative: they do not execute selectors, conversions or runtime corrections. Metadata-only work changed neither R adapters nor schemas/scientific policies; the current checker has a narrow reviewed CropScape access-URL exception. The [current audit](../catalog_gap_audit.xlsx) distinguishes verified implementation defects from provider evidence gaps (20 findings: 12 P1, 8 P2); these priorities apply before the affected operation, not to every record in a family. AQS and CropScape execution limitations remain distinct from their completed metadata corrections.

### Included records with explicit qualifications

The current specifications determine membership, flags and qualifications. Inclusion does not certify native-array decoding, data availability, an analysis-specific selection or backend execution. `ProductVariable.metadata_gaps` uses [MissingReasonEnum](../amadeus_schema/src/amadeus_schema/schema/amadeus_common.yaml); it describes metadata interpretation/extraction, not observation QA. An absent optional field, empty theme list or catalog-local CRS is not automatically an error or an investigation flag.

The [mapping workbook](../catalog_schema_excel_mapping_with_unmapped.xlsx), `amadeus_catalog.yaml` rows 220/223/224 and `amadeus_common.yaml` row 47, marks `quality_flag_vocabulary`, `harmonization_note`, `metadata_gaps` and `MissingReasonEnum` **No Match** to source Excel columns.
