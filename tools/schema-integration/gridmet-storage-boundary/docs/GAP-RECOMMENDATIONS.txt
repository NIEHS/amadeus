PRINCIPLE
Resolve policy/coverage/independent replay before feature expansion. Keep scientific Amadeus calls unchanged; enforce actual data automatically after calculate, during writing/loading and at saved-store open. Stable definitions are checked at build. New runtime rules require a documented gap; avoid duplicate checks without a changed input or trust boundary. No AI model executes validation.

PRIORITY 1 — QUALIFY THE CURRENT BOUNDARY
Complete scientific decisions and critical rule-level control/rejection cases. Replay one matched request on an independent/affected stack. Test incomplete-load/publication/retry behavior on the target filesystem. Review provenance truth and supported query/trust boundaries. Record actual AI assistance and real human decisions. Keep all unresolved approvals visible.

PRIORITY 2 — DEMONSTRATE OPERATIONAL VALUE AND EXPANSION
Measure the exact corrected release under matched workload/components. Agree deployment controls and supported concurrency/retention. Then qualify a contrasting dataset and selected backend separately. Add metadata sources and migrations only with versioned authority/conflict rules and compatibility tests.

ONE TRACEABLE RECORD PER CHANGE
Gap ID → authoritative source/version/observed fact or proposed policy → rule ID and implementation hash → valid/invalid test IDs and results → reviewer/date/decision/rationale → approved scope/release hash. Keep machine acceptance, human approval and publication completion distinct. Historical suite evidence is not an individual-rule negative test. Unknown authorship stays unknown.

EFFICIENT TESTING
Use cached identical sources to isolate integration cost and correctness; label them cached. Use minimal fixtures for rejection tests and one ordinary small request for replay. Run targeted tests during edits and a full scoped qualification suite for a changed release. Keep monitoring outside row loops. Reuse JSON Schema, generated SQL, recorder and database gate; prefer metadata-driven scope over copied per-dataset scripts. Optional signing/locking/immutable-store controls require a separate explicit design and tests, not a hidden addition.

DECISION
A bounded operational trial needs reviewed scientific/acceptance policy, demonstrated critical rejection coverage, independent replay, clear failure/retry/access behavior and an agreed limited trust model. Broader production additionally needs supported storage/concurrency/recovery controls and measured cost appropriate to scale. Human decisions remain pending; this document does not set an automatic production flag or guarantee scientific truth.
